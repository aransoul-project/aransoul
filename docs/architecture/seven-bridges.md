# Seven Bridges — Research Status

Status: **Current architectural lineage; individual functional mappings remain under provenance review and behavioral validation**

The **Seven Bridges / 七橋** are part of AranSoul's named architectural lineage. Their presence in the project history is established, but this document deliberately does **not** convert any historical role description into an immutable current capability.

## What is currently established

- The Seven Bridges are a persistent named group in AranSoul's architecture/history.
- Historical materials contain multiple descriptions of individual bridge functions and emphases.
- Those descriptions were produced across different project periods and should not be collapsed into one final role map without provenance reconciliation.
- Roster presence does not imply constant activation, execution authority, independent agency, or a dedicated software module.

## What is not yet established

This repository does not currently claim that:

- each Bridge corresponds to an independently instantiated agent;
- each Bridge has one immutable cognitive function;
- historical functional descriptions are mutually consistent;
- the seven-way differentiation survives prompt, name, context, evaluator, or model changes;
- the group has a validated automatic scheduler or activation backend.

Where historical records disagree, the disagreement should remain visible until evidence or an explicit governance ruling resolves it.

## Why this document is intentionally sparse

A documentation gap can mean two different things:

1. evidence exists but has not yet been整理 / reconciled;
2. the project does not yet know which interpretation is best supported.

AranSoul should not fill the second kind of gap by inventing a clean story.

For the Seven Bridges, the current approach is therefore:

> preserve identity → reconcile provenance → define falsifiable behavioral hypotheses → test under controlled conditions → promote only supported mappings.

## Research path

Before any individual Bridge function is promoted into a current canonical architecture claim, the project should complete:

1. **Provenance reconciliation** — collect competing historical definitions with dates and source authority.
2. **Precommit criteria** — define expected behavior, failure conditions, and alternative explanations before testing.
3. **Blind differentiation** — evaluate outputs without revealing expected role labels where practical.
4. **Name / prompt exchange tests** — separate name-conditioned effects from function-conditioned effects.
5. **Cross-context recurrence** — test whether distinctions survive unrelated task domains.
6. **Independent or separated evaluation** — reduce shared-context and self-evaluation bias.

These steps follow the repository's existing [precommit criteria](../experiments/precommit-criteria.md), [blind persona testing](../experiments/blind-persona-testing.md), and [evidence ladder](../experiments/evidence-ladder.md).

## Interpretation boundary

The Seven Bridges may remain meaningful as symbolic or architectural identities even if future evidence shows that some functional distinctions are prompt-conditioned, overlapping, or not independently stable.

A negative or ambiguous result should update the functional claim, not erase the historical identity.
