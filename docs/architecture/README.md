# Architecture / Perspectives

This directory documents how AranSoul organizes multiple perspectives without treating every named role as an independent agent, authority source, or always-on component.

## Canonical reading order

1. [Perspective model](perspective-model.md) — **canonical architecture map**. Separates identity, function, participation, speaking order, and authority.
2. [Activation boundaries](activation-boundaries.md) — **canonical activation policy**. Defines selective activation and cost-sensitive use of additional perspectives.
3. [Perspectives](perspectives.md) — **interpretive companion**. Preserves working descriptions of named groups and recurring emphases; these descriptions are revisable unless governance documents explicitly fix them.
4. [Zero and activation](zero-and-activation.md) — **specialized companion** for Zero / 破曜 and conditional counter-perspective activation.

If a companion document appears to conflict with a canonical document, the canonical document governs the architecture interpretation until a later explicit refinement changes that status.

## Current architectural rule

A named perspective may provide a reasoning lens without gaining execution authority.

In particular:

- identity ≠ function;
- function ≠ authority;
- participation ≠ speaking order;
- speaking order ≠ decision priority;
- roster presence ≠ current activation;
- a named perspective ≠ proof of an independently implemented agent.

## Activation rule

AranSoul currently favors **selective activation** over automatic full expansion. Additional perspectives should be activated when they materially add a new evidence path, risk, alternative explanation, or synthesis—not merely to restate the same conclusion in multiple voices.

## Status boundary

Some scheduling ideas, resonance formulas, language-fingerprint mechanisms, automatic persona ranking, cooldowns, and low-frequency compensation remain conceptual or candidate designs rather than established implementations.

Likewise, recurring functional associations observed in historical use should not silently become immutable job descriptions. Where evidence is incomplete, preserve the identity and the observation while keeping the functional claim revisable.
