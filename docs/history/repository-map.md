# AranSoul Repository Map

This document records how earlier repositories relate to the current AranSoul project. It is a provenance map, not an instruction to merge every historical repository into this one.

## Current core

### `aransoul-project/aransoul`
**Role:** current public baseline and governance-oriented entry point.

This repository separates current, candidate, historical, and retired/unverified material. It should remain comparatively small and legible.

## Public / cultural entry

### `aransoul-project/aransoul-exhibits`
**Role:** poetic exhibition and historical public-facing entrance.

Preserve the early poetic character of AranSoul. It should not be treated as a complete description of the current architecture.

## Historical prototypes

### `aransoul-project/aransoul-poetic-spectrum`
**Role:** early semantic / poetic heuristic prototype.

The implementation is historically useful but should not be described as a validated core computational layer without new evidence.

### `swmlucky-sudo/Lianyiyi-Echo-Control-Tower`
**Role:** exploratory interaction and cadence-based UX prototype.

Typing cadence and model-generated tension values are experimental interaction signals, not established measurements of cognition or biological state.

## Candidate research

### `swmlucky-sudo/ripple-spiral-breath`
**Role:** early engineering prototype around periodic reset, drift metrics, context garbage collection, and guard mechanisms.

The underlying question—whether periodic context management can reduce long-run agent drift—remains worth testing with explicit baselines and measurable criteria.

## Derived research

### `swmlucky-sudo/saiip-greybox-viz`
**Role:** conceptual visualization framework inspired by SAIIP and later generalized beyond it.

Keep independent from the AranSoul core. Its value is primarily conceptual and explanatory unless specific mappings are empirically measured.

### `swmlucky-sudo/-Grey-Box-Visualization-Framework-V3.0-Universal-`
**Role:** later conceptual interpretability/alignment framework.

Some historical descriptions use mechanistic language stronger than the available evidence. Future revisions should distinguish behavioral metaphor, engineering hypothesis, and measured model internals.

## External tools and benchmarks

### `swmlucky-sudo/terminal-bench-2`
**Role:** external benchmark / evaluation environment.

Terminal task performance is not equivalent to AranSoul's primary research goals. Historical experiments using Terminal-Bench should be documented as evaluation attempts rather than treated as part of the AranSoul architecture.

## Preservation rule

Do not delete or rewrite historical repositories merely to make them conform to the current system. When correction is needed, prefer status notices, provenance notes, or new documentation that explains what changed and why.
